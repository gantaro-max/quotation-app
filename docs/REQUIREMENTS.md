# 見積作成システム 要件定義書 (改訂版)

- **ドキュメント更新日:** 2026 年 8 月 20 日
- **対象システム:** Web ブラウザベース見積作成アプリケーション

## 1. システム概要

本システムは、営業担当者がブラウザ上で効率的に見積書を作成・編集・印刷、保存するための業務アプリケーションである。
Excel ライクな操作性（キーボード移動、範囲選択、コピペ）と、リアルタイムなプレビュー機能（WYSIWYG）に加え、**案件ごとの階層管理機能（枝番管理）**を兼ね備える。

## 2. 業務フロー・ユーザー

- **利用者:** メディカル担当者（各拠点に所属）
- **利用シーン:**
  1.  ログインを行う（パスワードはハッシュ化され安全に管理される）。
  2.  過去の見積を案件名や階層構造（枝番）から検索・参照する。
  3.  既存見積から「枝番作成」を行うか、完全新規作成を行う。
  4.  見積内容（明細）を入力する（Excel からのコピペやマウス範囲選択が可能）。
  5.  提出済みの見積は、誤って上書きしないよう「改版（枝番作成）」フローへ誘導される。
  6.  印刷プレビューを確認し、PDF 保存または印刷を行う。

## 4. データ要件（エンティティ定義）

### 4.1 ユーザー (User)

| 項目名         | 型     | 説明                                      |
| :------------- | :----- | :---------------------------------------- |
| id             | number | ユーザー ID                               |
| name           | string | 氏名                                      |
| email          | string | メールアドレス（ログイン ID）             |
| passwordHash   | string | **ハッシュ化済みパスワード (SHA-256)**    |
| departmentName | string | 所属部署名                                |

> ⚠️ **既知の制限:** ユーザーは所属営業所（branchId）を持たない（部署名のみ）。そのためフロントエンドは編集画面の営業所初期値をユーザーごとに出し分けられず、ログイン直後は常に固定の営業所（ID: 9443）がデフォルト選択される（[LoginPage.tsx](../frontend/src/components/LoginPage.tsx)）。ユーザー単位で営業所を管理したい場合は `users` テーブルへの `branch_id` 追加、または `sales_staffs` との紐付けが必要。

## 5. UI/UX・非機能要件

1.  **操作性:**
    - Excel ユーザーが違和感なく操作できるよう、キーボード操作（矢印移動、Delete クリア）とマウス操作（ドラッグ範囲選択）の両方をサポートする。
2.  **安全性:**
    - パスワードはハッシュ化して保存し、平文での管理を行わない。
    - 提出済みの見積もりは安易に上書きされず、履歴（枝番）として残るフローを強制する。
3.  **一覧性:**
    - 案件名や親番号でグルーピング表示することで、多数の見積履歴から目的のものを探しやすくする。

## 6. 技術選定・実装方針

### 6.1 バックエンド

- **技術スタック:** Java (Spring Boot) + **MyBatis** + MySQL (または H2)
- **採番ロジック:** 重複防止のため、現在時刻(秒単位)やランダム値を組み合わせたユニークな番号を発行する（新規作成時のみ。枝番作成時はフロントエンドが既存番号の末尾を+1する）。

### 6.2 フロントエンド

- **技術スタック:** React + TypeScript
- **コンポーネント構成:**
  - `LoginPage`: 認証画面
  - `QuotationList`: 階層構造付き検索一覧
  - `EditScreen`: Excel ライクなグリッド操作機能付き編集画面

## 7. 既知の制限事項・技術的負債

- **ユーザーの所属営業所が管理されていない:** 4.1 参照。ログインユーザーごとの営業所初期値が機能しておらず、常に固定値（ID: 9443）になる。対応方針決定済み → [SPEC-001](specs/001-user-branch-id.md)
- **見積コピー用バックエンドAPIが未使用:** `POST /api/quotations/{id}/copy`（[QuotationController.java](../backend/src/main/java/com/quotationapp/backend/controller/QuotationController.java)）と対応する `QuotationService.copy()` が実装されているが、フロントエンドはこれを呼び出していない。実際の「コピーして新規作成」機能（F-015想定の挙動）は、フロントエンド側で入力状態をリセットし、通常の新規作成 (`POST /api/quotations`) を呼ぶことで実現している。対応方針決定済み（バックエンド側を削除） → [SPEC-002](specs/002-remove-unused-copy-api.md)
